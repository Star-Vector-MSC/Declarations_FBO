# Declarations FBO

Telegram-бот для подготовки Excel с номерами таможенных деклараций и страной происхождения для поставок Wildberries FBW (FBO). Готовые файлы пользователь загружает в кабинет WB вручную.

## Как пользоваться

Пришлите боту **номер поставки обычным сообщением** — он выдаст Excel с кнопкой «Готово». По кабинету и дате файлы можно выбрать кнопками; общий запрос по дате возвращает ZIP.

- Готовые Excel хранятся внутри SQLite. Выдача и меню не обращаются к Google Таблицам и PostgreSQL.
- База обновляется при запуске и каждые 6 часов. Кнопки «Обновить базу» и «База файлов» позволяют обновить снимок вручную и узнать его состояние.
- Выдача файлов и запись галочек работают независимо. Можно сразу отправлять следующий номер; подтверждения обрабатываются последовательно в очереди, повторять запрос не требуется.
- После ручной загрузки в WB нажмите «Готово»: бот проставит и перепроверит галочки в таблице плана, затем удалит файл из кэша.
- Отметки, поставленные вручную в таблице, проверяются раз в 5 минут. Частично отмеченные поставки снимаются с выдачи. Изменение состава, даты, количества или страны блокирует файл с пояснением до обновления базы.
- Изменение свободного остатка не удаляет готовый файл между плановыми обновлениями: ДТ соответствует времени снимка, указанному при выдаче. Для пересчёта по текущему остатку нажмите «Обновить базу».
- Если файла нет, бот предложит обновить базу. При ошибке обновления предыдущий снимок сохраняется с прежним временем.

Галочки означают подтверждение пользователя. Бот не проверяет сохранение ДТ внутри WB.

## Настройка

Нужны Python 3.11+, PostgreSQL с таблицами `wb_supplies_goods` и `article`, сервисный аккаунт Google и Telegram-бот от BotFather.

```bash
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env`, заполните его локально или настройте переменные окружения хостинга:

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен отдельного Telegram-бота |
| `TELEGRAM_ALLOWED_USER_ID` | Единственный пользователь с доступом, только личный чат |
| `GOOGLE_APPLICATION_CREDENTIALS` | Путь к JSON-ключу сервисного аккаунта |
| `RECEIPTS_SPREADSHEET_ID`, `RECEIPTS_SHEET_GID` | Таблица и лист приходов |
| `SHIPMENTS_SPREADSHEET_ID`, `SHIPMENTS_SHEET_GID` | Таблица и лист плана отгрузок |
| `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`, `PGSSLMODE` | Подключение к PostgreSQL |
| `WB_BASE_TEMPLATE` | Пустой XLSX-шаблон, по умолчанию `assets/wb_declaration_template.xlsx` |

JSON-ключ положите в `secrets/google-service-account.json` или укажите другой путь. Таблицу приходов откройте сервисному аккаунту как читателю, таблицу плана — как редактору для галочек. PostgreSQL используется только для чтения.

Пароли с `#`, пробелами или кавычками корректно заключайте в кавычки согласно формату dotenv. Переменные окружения имеют приоритет над `.env`; ID владельца перечитывается из локального файла, если он там задан.

Запуск:

```bash
python -B -u telegram_bot.py
```

В Windows можно использовать `run_bot.cmd`. Команда `/myid` покажет ваш Telegram ID; внесите его в настройки. До настройки ID файлы недоступны.

## Данные и бизнес-правила

Одобренные строки без номера поставки или кабинета пропускаются до заполнения; их количество показывается в состоянии базы. Строка без артикула WB в уже назначенной поставке блокирует всю поставку, чтобы не выдать неполный Excel.

План: статус «Одобрено», дата отгрузки, кабинет, номер поставки, артикул WB, базовый wild, количество и свободный остаток. Столбцы определяются по заголовкам. Из двух колонок «Название магазина» первая означает кабинет, вторая — товар.

Приходы сортируются по фактической дате от новых к старым, при одинаковой дате сохраняется порядок строк. Складывается «Кол-во к заказу» до первого значения суммы **не меньше свободного остатка**. Выбирается ДТ граничной строки. Недостаточное количество или отсутствующая ДТ блокирует файл для проверки.

Точный артикул продавца и баркод берутся из PostgreSQL по кабинету, поставке и артикулу WB. Суффиксы `D/d/d2` сохраняются в Excel; базовый wild используется только для поиска приходов. Сверяются количество и полный состав поставки.

Комплект `wild103` состоит из `wild1945` и `wild2135` (по одной штуке). По явно согласованному исключению ДТ берётся из единственного заполненного номера ДТ в приходах `wild1945`; ДТ и машина `wild2135` для этого выбора не проверяются. Используются фактически прибывшие количества источника, достаточные для свободного остатка комплекта. Если заполненных номеров ДТ нет или их несколько, требуется проверка. Конкретный номер ДТ в коде не закреплён; артикул комплекта в Excel сохраняется.

Правило согласованного ассортимента: казаны — код страны `860`, остальные товары — `156`. При изменении ассортимента это правило нужно проверить.

## Что лежит в проекте

- `telegram_bot.py` — сообщения, кнопки и выдача файлов.
- `file_cache.py` — SQLite, обновление и очистка.
- `completion.py` — подтверждения и галочки в таблице.
- `export_templates.py` — сборка Excel.
- `wb_declarations.py` — чтение таблиц и расчёт ДТ.
- `assets/` — пустой шаблон; `tests/` — проверки; `.github/` — автоматический запуск тестов.

## Хранение и эксплуатация

Файл удаляется из выдачи только после подтверждения всех строк поставки. Для повторной подготовки снимите галочки и нажмите «Обновить базу». Кнопки под уже выданными файлами продолжают работать после очистки кэша.

`data/declarations.sqlite3` содержит рабочие Excel. `runs/telegram_batches` хранит подтверждения кнопок; временные копии отправки удаляются после выдачи. `exports` содержит ручные выгрузки. Эти каталоги, `.env`, ключи и профили браузера не публикуются.

Для хостинга нужны постоянные диски для `data/` и `runs/`, секреты и один работающий процесс polling. Не запускайте локальную и серверную копии одного бота одновременно. Расписание работает, пока процесс запущен. Автоматическое развёртывание на хостинг в этом репозитории не настроено.

## Проверки

```bash
python -B -m unittest discover -s tests -v
```

Тесты используют искусственные данные и подменяют внешние API. GitHub Actions запускает их на Linux.

## Изолированный расчётный модуль планирования

`planner.py` содержит только расчёт и проверку входных данных; к Telegram-боту он ещё не подключён и таблицу не изменяет. `build_plan` получает снимок строк листов «тест» и справочника упаковки. Результат — предложение с количествами, причинами, предупреждениями и недобором; один проход не гарантирует оптимального заполнения машины.

Схема источника проверена по Google Sheets API: на листе «тест» столбец I с заголовком «Название товара» содержит товарные группы, включая «Газовые горелки туристические» и «Парфюм для дома». Отдельного столбца «Группа товара» или «Категория товара» в этом источнике нет. «Процент загрузки по категории» — расчётный числовой показатель, не название группы. Поэтому входной контракт этого модуля читает группу именно из «Название товара»; поле результата `product` сохраняет это значение. Конкретные названия моделей не подставлять в это поле вместо группы при подготовке снимка. Если схема источника изменится, контракт надо обновить явно.

Обе запрещённые группы исключены для всего wild во всех кабинетах, включая обязательные позиции. Пустой/ошибочный свободный остаток или пустая/нестроковая группа хотя бы в одной строке также блокируют весь wild. Проверки только локальные; контейнерная приёмка не настроена. Рабочий бот, публикация и запись планов — отдельный этап.

## Постоянная память планировщика

`planner_memory.py` хранит подтверждённые правила, примеры, области действия и историю отмен в отдельной SQLite. Он пока не подключён к Telegram, расчёту или прогнозированию. Новые записи остаются черновиками до подтверждения; примеры не становятся обязательными правилами.

[Устройство и восстановление](docs/planner-memory-storage.md), [читаемая память](docs/planner-memory.md), [машинный архив](docs/planner-memory-ledger.md). Машинные копии сохраняет ассистент в обоих согласованных репозиториях; автоматического GitHub-клиента и токена в боте нет. Данные SQLite и локальные копии в data/ исключены из Git. Код модулей прошёл независимое ревью и локальные тесты; интерфейс бота и анализ динамики — следующий этап.
