# Память помощника: резервирование и восстановление

## Состояние

Требование: хранить резервные копии памяти в двух GitHub-репозиториях — в базе знаний и в репозитории бота. Режим публикации рабочей памяти в репозиторий бота ещё не выбран. Этот файл описывает процедуру; он не является полной копией памяти или проверенным экспортом SQLite.

Хранилище SQLite и машинный импорт пока не реализованы. Перезапуск сам по себе не очищает файловую SQLite. Внешняя копия нужна на случай потери файла или диска.

## Состав памяти

Сохранять подтверждённые инструкции, причины правок, область действия, срок, историю подтверждений и отмен. Исключения отдельного плана не превращать автоматически в глобальные правила.

Полный журнал с рабочими правками хранить в закрытых репозиториях. Пока репозиторий публичный, допускается только явно проверенная общая версия без рабочих данных; она не позволяет восстановить полную память.

Не публиковать ключи, токены, снимки таблиц, остатки, сведения поставок и локальную SQLite с рабочими данными.

## Порядок резервирования через ассистента

1. Получить согласованную версию памяти и проверить состав.
2. Перед записью прочитать обе удалённые версии; объединить историю без потери новых записей и отмен.
3. Для полной копии публиковать один и тот же проверенный экспорт в обоих закрытых репозиториях. Для публичной общей версии явно указать, что копия неполная.
4. Проверить каждую запись повторным чтением. Записать результат по каждому репозиторию отдельно; успех одного не означает успех второго.
5. Если одна запись не удалась, сохранить локальную полную версию и явно отметить отставшую копию. Не объявлять резервирование завершённым.

После появления машинного формата проверять совместимость версии, целостность и пробное восстановление в отдельную временную базу. Существующую рабочую базу не перезаписывать без проверки и отдельной резервной копии. Читаемый Markdown с правилами не считать автоматически совместимым с импортом.
