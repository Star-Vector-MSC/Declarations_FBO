## Подтверждённые правила

| ID | Область | Правило |
|---|---|---|
| FBO-001 | Постоянно | Газовые горелки и парфюм для дома не отгружать на FBO. В источнике: «Газовые горелки туристические», «Парфюм для дома». Обязательная позиция или причина исключения этот запрет не отменяет. |
| FBO-002 | Базовый отбор | Минимум продаж за 3/7/14/30 дней ≥ 8 ед./день включительно, текущий остаток в днях ≤ 10, остаток по wild ≥ 30 дней. |
| FBO-003 | Приоритет | Сортировать по первому «Прогнозные остатки в днях» (7-дневному прогнозу), от меньшего к большему. Одобрение и приёмка в нём уже учтены. |
| FBO-004 | Пополнение по спросу | Подтверждённый рост — 10–13 дней общего запаса; стабильность без признаков падения — 10; плавное снижение с небольшими колебаниями — максимум 7; подтверждённое резкое падение — без автоматического пополнения. Ошибочные или недостаточные данные не считать достоверным падением или стабильностью. |
| FBO-005 | Упаковка | «Монопаллета», второй набор упаковочных заголовков справочника. Минимум целые короба; предпочтительны 0,25 / 0,5 / 1 паллеты. Меньшие доли допустимы по необходимости. |
| FBO-006 | Машина | Вместимость только 20 или 33 паллеты. Стремиться заполнить; при недоборе сообщать и предлагать явное изменение условий, без самовольного ослабления правил. |
| FBO-007 | Остаток | Общий свободный остаток контролировать по wild для всех кабинетов совместно. Физический остаток не равен доступному; черновики сами по себе не резервируют склад. |
| FBO-008 | Запись | До отдельного разрешения записывать планы только в «Планирование FBO — ТЕСТ». Исходный «Отгрузка FBO» планировщику не менять. |
| FBO-009 | Стоимость | Бесплатные инструменты либо текущая подписка; отдельный платный AI API не согласован. |
| FBO-010 | Память | Новое постоянное правило требует подтверждения владельца. Хранить причины правок, область и срок действия; исключения плана не повышать автоматически до глобальных правил. |
| FBO-011 | Резервирование | Полная память в ai-knowledge и в репозитории бота; обновление через ассистента, проверка обеих копий отдельно. Полная копия в публичном репозитории компании явно разрешена Иваном. |

## Пример, который нельзя превращать в постоянное правило

Вентиляторы добавлялись по просьбе руководства вне базового отбора. Это пример исключения конкретного плана, а не разрешение постоянно включать все вентиляторы. Условия и срок следующего такого поручения нужно получить явно.

## Динамика заказов и качество данных

Источник — лист «Количество заказов»: дневная история по уникальному артикулу WB, связанная с wild. Для тренда анализировать дневной ряд, недельные изменения, устойчивость и колебания; не полагаться только на готовый значок «Тренд». Пустые значения не превращать в нули. Заказы при отсутствии товара не доказывают низкий спрос; непонятные причины и недостаток истории отмечать отдельно. Проценты для категорий тренда ещё не откалиброваны; сама аналитика в боте не реализована.

На проверке 2026-10-27 Иван подтвердил ошибку данных в последнем столбце «26.10»: реального массового падения не было, он проверяет скрипт. До исправления этот день не использовать как корректное наблюдение для прогноза или автоматического отказа в пополнении. После исправления перечитать источник. Это временная отметка качества конкретной выгрузки, не постоянное исключение даты на все годы.

## Как дополнять память через ассистента

Сохранять только подтверждённое: что изменено, причина, область (все планы / товар / конкретный план), срок, заменяет ли запись старое правило. Если область неясна — уточнять. Отменённое правило помечать отменённым с причиной, не стирать историю молча. Не включать снимки таблиц, ключи и токены.

Новые записи бота не появляются в GitHub автоматически в выбранном режиме. До реализации SQLite-хранилища этот файл обновляет ассистент по поручению владельца. После реализации — отдельно проверять экспорт, сохранение и восстановление; согласовывать совместимый формат вместо предположения, что произвольный Markdown импортируется автоматически.
